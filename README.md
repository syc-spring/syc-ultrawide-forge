# UltrawideForge · 超宽画卷生成器

> 菜鸟广告 AI 工程实践题 · 题目一:突破图片生成宽高比限制
>
> 单次 Image API 的宽高比上限约 **3:1**。本项目在不依赖单次生成超比例图片的前提下,通过
> **分镜规划 + 滚动外绘(rolling outpainting)+ 接缝融合**,稳定产出 **6:1、8:1** 乃至 20:1 的
> 完整连贯图片,并提供可实际操作的在线 Demo。

---

## 一、方案原理

### 1. 为什么不能"直接拉大画布"

- 拉伸会导致主体变形;
- 上下留白不产生内容,不满足"完整图片"要求;
- 生成后裁切会丢失构图信息。

### 2. 核心算法:滚动外绘三步走

```
用户提示词 + 目标比例(如 8:1)
        │
        ▼
┌─────────────────── ① 分镜规划 ───────────────────┐
│  将画面拆为 N 个"从左到右"的段落(模板或 LLM 规划),   │
│  保证叙事/构图有全局设计,而不是逐块盲画              │
└──────────────────────────────────────────────┘
        │
        ▼
┌─────────────────── ② 滚动生成 ───────────────────┐
│  Tile 1:images/generations 文生图(3:1 以内)       │
│  Tile k:取累积图右缘 overlap 条(默认 25%)作锚定,    │
│          构造左实右空的画布 → images/edits 续画      │
│  (单次调用始终不超过 API 的 3:1 限制)              │
└──────────────────────────────────────────────┘
        │
        ▼
┌─────────────────── ③ 接缝融合 ───────────────────┐
│  a. 色彩迁移:以重叠区为参照做逐通道均值/方差匹配,     │
│     抑制相邻块色调漂移(增益限制在 0.7~1.4)          │
│  b. 线性羽化:重叠区做 cross-fade,过渡带=整个重叠区   │
│  c. 精确收口:最后一块按剩余宽度裁齐,总宽分毫不差      │
└──────────────────────────────────────────────┘
        │
        ▼
   5792×724 工作图 → 终端等比输出 8192×1024(8:1)完整全景 PNG
```

**几何模型**(以 8:1@1024、tile 2172×724[该 API 的 3:1 原生分辨率]、重叠 25% 为例):

| 量 | 值 |
|---|---|
| 单块 tile | 2172×724(3:1,恰好卡在 API 上限内) |
| 重叠区 | 543px |
| 每块推进 | 2172−543 = 1629px |
| 工作总宽 | 5792px(8×724)→ 4 块(末块仅保留 905px 裁齐收口) |
| API 调用 | 4 次(1 次文生图 + 3 次编辑续画) |
| 最终输出 | 等比放大至 8192×1024(仅一次终端放大,全程无拉伸变形) |

### 3. 一致性保障手段

| 手段 | 作用 |
|---|---|
| 全局分镜规划 | 每块有明确内容主题与空间位置语义,避免"各画各的" |
| 锚定条外绘 | 编辑画布左端携带上一块的真实右缘,模型必须"接得上" |
| 续画提示词约束 | 强制保持地平线、透视、光照方向、色调统一;禁止边框/水印/重复 |
| 色彩迁移(match_color) | 逐块向累积图对齐均值/方差,抑制累积色漂 |
| 线性羽化拼接 | 重叠区 cross-fade,消除硬缝 |
| 参照累积图而非上一块 | 色彩基准始终是"全景整体",误差不随块数累积 |

## 二、在线 Demo

### 页面功能

1. **输入提示词**(内置 4 组示例一键填充)
2. **选择目标比例**:3:1 / 6:1 / 8:1 / 10:1 / 12:1 / 21:9,或自定义任意 `W:H`(0.5~20)
3. **选择输出高度**:512 / 768 / 1024 / 1536
4. **工程读数**:提交前实时预估输出尺寸、分块数、API 调用次数
5. **实时进度**:SSE 推送,胶片条逐块"显影",展示每块缩略图与分镜文案,断线自动降级轮询
6. **结果查看**:拖拽平移的全景查看器 + 位置小地图 + **接缝检查模式**(红线标注拼接位置)
7. **历史记录 / 案例集**:最近生成任务回看;samples/ 中离线案例展示

### 本地运行

```bash
git clone <repo-url> && cd ultrawide-forge
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env       # 填入 OPENAI_API_KEY 等
uvicorn app.main:app --port 8000
# 打开 http://127.0.0.1:8000
```

> 未配置 Key 时服务自动进入 **Mock 演示模式**(确定性程序化图像),
> 可完整体验提交流程、进度、拼接与查看器,便于审阅与开发自测。

### Docker 运行

```bash
docker build -t ultrawide-forge .
docker run -p 8000:8000 -e OPENAI_API_KEY=sk-xxx \
  -v $(pwd)/results:/app/results ultrawide-forge
```

### 云端部署(在线 Demo 挂载)

任意支持 Docker/长驻进程的平台均可,例如:

- **HF Spaces**(Docker Space,免费档即可演示,`CPU basic` 即可,耗时取决于上游 API)
- **Render / Railway / Fly.io**:直接用仓库 Dockerfile,环境变量注入 Key
- 注意:SSE 需要 close buffering(代码已发 `X-Accel-Buffering: no`);若挂 Nginx 需 `proxy_buffering off`

## 三、项目结构

```
ultrawide-forge/
├── app/
│   ├── main.py        # FastAPI 路由:生成/SSE 进度/结果/能力探测
│   ├── config.py      # 环境变量配置(.env)
│   ├── provider.py    # OpenAI 兼容 Provider(generations/edits,重试,b64/url 双兼容)
│   │                  #  └ 附 MockImageProvider:无 Key 流程演示
│   ├── planner.py     # 分镜规划:模板模式(默认)+ LLM 模式(可选,失败自动回退)
│   ├── stitcher.py    # 画布构建/色彩迁移/线性羽化/精确裁齐
│   ├── pipeline.py    # 滚动外绘编排(异步任务,SSE 事件流)
│   └── jobs.py        # 内存任务存储 + 事件总线
├── static/            # 前端单页应用(无构建,原生 HTML/CSS/JS)
├── samples/           # 6:1、8:1 实际生成案例(含 meta.json)
├── results/           # 运行产物(每任务:final.png + tiles/ + meta.json)
├── Dockerfile
├── requirements.txt
└── .env.example
```

## 五、实现方式、模型、依赖与工具使用说明

### 5.1 第三方 API

| 项 | 选择 | 使用情况 |
|---|---|---|
| 图像模型 | `gpt-image-1.5`(OpenAI 兼容接口,HR 提供的 Image API) | 经实测该服务单次上限恰好 **3:1**:请求 `3072x1024` 时实际返回 `2172×724`(比例 3.00),与题目设定一致 |
| 图像生成 | `POST /v1/images/generations` | 首块文生图 |
| 图像编辑 | `POST /v1/images/edits` | 后续各块续画(multipart 上传锚定画布);实测左缘锚定条像素级保留(均值偏差 <2%) |
| 分镜规划(可选) | `POST /v1/chat/completions` | `PLANNER_MODEL` 配置后启用,默认模板模式零依赖 |
| 质量盲评 | 独立视觉模型(一次性离线评估) | 用于第四节两个案例的成图质量打分,不参与生成链路 |

**对该 API 的实测适配**(全部已在代码中处理):

- `gpt-image-1` 在该服务上被注入不支持的 `complexity` 参数而 400,故选用 `gpt-image-1.5`;
- `quality` 参数不发送(避免触发上游 complexity 校验),`.env` 默认 `IMAGE_QUALITY=default`;
- API 返回分辨率可能与请求不同(如 3:1 请求返回 2172×724 而非 3072×1024),
  Provider 层统一 `resize_to` 归一化,并把 tile 规格配置为**原生返回值 2172×724**,全流程零缩放直拼;
- 编辑画布待填区用**白色**填充(`EDIT_FILL=white`),该服务对白色区域的"补全续画"语义最稳
  (官方 `transparent` 外绘语义未在本服务验证,保留为可选项);
- 响应兼容 `b64_json` 与 `url` 两种返回;网络失败指数退避重试 3 次。

## 六、已知问题与效果限制(诚实披露,含真实案例中的实际观察)

1. **接缝处可能有轻微"鬼影"**:重叠区 cross-fade 时,若续画块对锚定区内容重绘产生小幅偏移
   (模型非确定性),过渡带内会出现半透明重影。**真实案例中已观察到**:6:1 城市卷 1/3 接缝处
   水面倒影有轻微密度突变。缓解:锚定条较短(25%)+ 提示词强调"左缘不变";水面/雾面等
   低频高反光内容最易受影响。Demo 的"接缝检查"模式专门用于审视此问题。
2. **结构线长程连续性**:贯穿全图的长结构(山脊线、地平线、马路边缘)在多块续画后可能出现
   轻微错位或"堆叠感"。**真实案例中已观察到**:8:1 雪山卷 50% 处山脊轻微堆叠。
   缓解:提示词显式约束"horizon height / ridge line 保持一致";更彻底的方案是接缝局部 inpaint
   二次修复,作为后续迭代方向(未实现)。
3. **色调长程漂移有界但不为零**:逐块色彩迁移把每块拉回累积图统计,但 4 块以上仍可能出现
   全卷色温"来回摆动"(8:1 雪山卷 75% 处有轻微跳变,被日出渐变部分掩盖)。
4. **长卷内容漂移**:比例越大(≥10:1),主体/风格一致性越难保持;超过 ~12:1 建议分段生成再拼。
5. **末块像素利用率**:最后一块按几何需要裁齐,8:1 时末块 2172px 仅保留 905px(≈42%),
   属"精确收口"的固定开销(无拉伸)。
6. **成本与时长**:实测单次调用 20~60s,6:1(3 块)约 2 分钟、8:1(4 块)约 2.5 分钟;
   成本 ≈ 单图的 N 倍。
7. **单进程内存任务表**:重启丢失任务历史(结果 PNG 落盘不丢);多 worker 部署需换 Redis 广播事件。
8. **该中转 API 的特定限制**:`gpt-image-1` 不可用(complexity 校验 400);`quality` 参数不可用;
   3:1 请求实际返回 2172×724 而非请求分辨率——Provider 已全部适配,但意味着原生单块分辨率
   上限约 2172px 宽。

## 七、运行验证

- **真实 API**(2026-11,`gpt-image-1.5`):
  6:1 → 6144×1024(3 块,124.9s)、8:1 → 8192×1024(4 块,150.4s),见「案例展示」;
- **Mock 模式**:6:1 → 6144×1024、8:1 → 8192×1024,尺寸精确,SSE/轮询降级/查看器/
  接缝标记全部通过(Playwright 端到端共 17 项断言全绿:Mock 模式 11 项 + 真实模式 6 项);
- **API 适配探测**:generations/edits 双端点、尺寸上限、quality 参数、锚定保留率均经过
  程序化探测验证(编辑后左缘均值偏差 <2%)。
